# Semantic Evolution Overview

## What Evolution Is

Semantic evolution is deterministic analysis of existing workflow artifacts and metadata to propose non-destructive improvements.

It evaluates:

- ERD structure
- sequence flows
- UI templates
- components
- semantic metadata
- MLAS and BTIF lineage
- tag ontology quality

## Proposal Generation

Evolution proposals are generated by:

- workflow/semantic_evolution.py

Proposal block fields:

- category
- target
- proposed_change
- rationale
- confidence
- semantic_impact
- governance_requirements

## Governance Application

Long-term safety gates are defined in:

- workflow/meta/governance_long_term.json

Required approvals can include:

- evolution_approval
- semantic_approval
- structural_approval
- sync_approval

Evolution apply mode is blocked until required approvals are explicitly provided.

## CLI Commands

- python3 workflow/cli.py evolve-feature --feature <slug>
- python3 workflow/cli.py evolve-all
- python3 workflow/cli.py evolve-preview

Optional apply mode:

- python3 workflow/cli.py evolve-feature --feature <slug> --apply --approve-evolution --approve-semantic --approve-structural --approve-sync
- python3 workflow/cli.py evolve-all --apply --approve-evolution --approve-semantic --approve-structural --approve-sync

Preview write mode:

- python3 workflow/cli.py evolve-preview --write

## AI Surfaces

Evolution AI surfaces:

- workflow/ai_prompts/ai_evolution_prompt.txt
- workflow/meta/ai_evolution.json

These allow AI tools to reason about deterministic improvement proposals and validate governance requirements.

## Example Evolution Proposals

1. ERD improvement proposal:
- Add explicit PK markers to entities.

2. Sequence improvement proposal:
- Add participant declarations and message arrows.

3. Metadata improvement proposal:
- Normalize semantic_tags and align BTIF route with deterministic assignment.

4. Tag ontology proposal:
- Review low-reuse tags that appear only once across features.
