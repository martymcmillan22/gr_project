# BTPE NDA Checklist

Use this checklist before sharing BTPE materials with any external person or organization.

## A. Pre-NDA Intake
- Counterparty legal name verified
- Counterparty primary contact identified
- Purpose of sharing documented
- Data sensitivity level assigned (Restricted/Confidential/Internal/Public)

## B. NDA Core Terms (Must Have)
- Parties correctly named
- Clear definition of Confidential Information
- Explicit inclusion of:
  - Rule systems
  - Model logic
  - Pattern documentation
  - Source code
  - Non-public datasets
- Use limitation: evaluation/collaboration only
- No reverse engineering clause
- No sublicensing/redisclosure without written consent
- Return-or-destroy clause at end of engagement
- Survival period after termination (recommended: 3-5 years minimum)

## C. IP Protection Terms (Critical)
- No license transfer implied by disclosure
- No ownership transfer implied by access
- Independent development carve-out reviewed carefully
- Residuals clause reviewed (avoid broad residual rights where possible)
- Derivative works ownership defined in your favor

## D. Operational Security Terms
- Access limited to need-to-know personnel
- Storage/security obligations specified
- Breach notification timeline defined
- Audit/cooperation language included for incidents

## E. Legal and Process Controls
- Governing law and venue acceptable
- Signature authority validated for both parties
- Effective date and term completed
- Fully executed copy stored in controlled repository

## F. Before Any Disclosure
- NDA status: Fully executed
- Shared materials watermark/label applied
- Minimum necessary information prepared
- Disclosure log entry created (what, when, to whom)

## G. Post-Disclosure Hygiene
- Track every document/version shared
- Record follow-up requests and responses
- Revoke access when no longer needed
- Trigger return/destroy certification at project close

## Red Flags (Pause Immediately)
- "Mutual trust" request with no signed NDA
- Request for full corpus or full rulebook before agreement
- Broad residuals rights request
- Refusal to include no reverse-engineering language
- Counterparty asks to train models on your confidential data without explicit commercial terms
