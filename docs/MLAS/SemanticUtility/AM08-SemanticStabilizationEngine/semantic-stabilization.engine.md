4. Stabilization process
Step 01 — Normalize:

Align: Convert harvested patterns into forms that match Relay/QPU blueprints.

Standardize: Ensure naming, structure, and semantics follow constitution rules.

Step 02 — Deduplicate:

Merge: Combine overlapping or redundant patterns.

Prune: Remove noisy or one‑off artifacts that don’t generalize.

Step 03 — Canonicalize:

Shape: Turn patterns into canonical templates (subject/branch/term/meta‑term).

Bind: Attach QPU origin and Relay IDs for traceability.

Step 04 — Validate:

Check against:

Directive File

Context Injection rules

North Star identity

Relay/QPU blueprints

VS Code AI Instructions

Session Map constraints

Reject: Any pattern that violates constitution or engine structure.

Step 05 — Promote:

Promote to:

reusable semantic templates

engine rules/config

pattern libraries

future session hints (non‑ephemeral guidance).

Flag: Potential constitution‑level changes for explicit human review only.

5. Phase relationship
Create Phase (1AM–4AM):

AM‑08 is inactive; structure is being defined, not stabilized.

Post Phase (5AM–8AM):

AM‑08 may prepare stabilization criteria but does not commit patterns.

Work Phase (9AM–12PM):

AM‑07 harvests; after harvest, AM‑08 runs stabilization over the collected output.

After Work Phase:

AM‑08 finalizes stabilized assets and makes them available to future sessions and AM‑09.
