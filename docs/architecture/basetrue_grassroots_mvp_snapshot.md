# BaseTrue Grassroots MVP Snapshot

Status: Canonical MVP Narrative Baseline  
Updated: 2026-08-08

## Purpose

This document defines the canonical MVP narrative for BaseTrue Grassroots.
It aligns product language with deterministic system behavior across backend, frontend, timeline orchestration, and publication outputs.

## Executive Definition

BaseTrue Grassroots is a deterministic incubation pipeline that transforms a raw user idea into a structured, investor-ready, and user-ready MVP.
The platform advances work through four governed phases:

1. Idea
2. Seed
3. Project
4. MVP

Each phase introduces explicit structure, intelligence, and operational capabilities while preserving deterministic inheritance and traceability.

## Phase Model

### Idea Phase: The Spark

Entry is intentionally minimal:

1. Title
2. Intentions
3. Vision

This phase maximizes accessibility and minimizes startup friction.

### Seed Phase: The Formation Layer

Promotion from Idea to Seed introduces thesis structure:

1. Title becomes thesis subject
2. Intentions become thesis direction
3. User writes Seed Thesis covering:
   1. What the idea is
   2. Why it matters
   3. Who it serves
   4. Where it should go

This is the bridge from creativity to deterministic structure.

### Project Phase: The Operational Engine

Promotion from Seed to Project activates the deterministic backbone:

1. Sector, Industry Group, Industry, Sub-Industry alignment
2. LFO Engine (Math, Language, Arts, Science)
3. Workflow Engine
4. CD/CI automation
5. SOP builder
6. Versioning and feature management
7. Timeline runtime and GUI endpoint

At this phase, project state is automatically formatted using economic, structural, and operational metadata from the 4 to 16 to 64 to 256 hierarchy.

Core user actions at Project:

1. Add features
2. Trigger deterministic version updates
3. Navigate timeline progression
4. Interact with generated GUI endpoint
5. Use Science (MBSP) surface for consumer synthesis

### MVP Phase: The Publishable Identity

Promotion from Project to MVP generates two deterministic publication outputs.

#### Investor E-Book

The external business identity, covering:

1. Thesis
2. Industry alignment
3. LFO structure
4. Workflows
5. CD/CI evolution
6. SOP operational plan
7. Business model
8. Market position
9. Future roadmap

#### Product Usage E-Book

The internal product identity, covering:

1. Product behavior
2. User interaction model
3. Workflow operation
4. SOP-guided usage
5. Update rollout model
6. GUI behavior
7. Onboarding path
8. Scale path

Both books are generated from deterministic project state, not ad hoc content.

## Deterministic Inheritance Contract

Grassroots enforces inherited structure through the global economic map:

1. 4 subjects
2. 16 SEVM branches
3. 64 industries
4. 256 sub-industries

This inheritance is append-only and deterministic by default.

## Runtime Contract Nuance

The canonical backend micro-template generator produces 256 rows for sub-industry scope.

Frontend behavior is intentionally resilient:

1. If backend micro templates are present, the micro surface resolves 256 rows.
2. If backend micro templates are absent, frontend fallback derives rows from available industry templates.
3. In current fallback shape, this can resolve to 64 rows when only industry-level inputs are present.

This is expected fallback behavior and not a contract violation.

## Canonical One-Paragraph Summary

BaseTrue Grassroots is a deterministic incubation pipeline that transforms a raw idea into a fully structured MVP through four governed phases: Idea, Seed, Project, and MVP. Users start with a simple title and intention, form a Seed Thesis, and then enter the Project phase where the system aligns work to the global 4 to 16 to 64 to 256 economic hierarchy, activates the four-surface LFO engine, and generates workflows, SOPs, versioning, features, and GUI endpoints. By MVP, Grassroots produces both an investor e-book and a product usage e-book, giving each project an external business identity and an internal user identity generated directly from deterministic project structure.
